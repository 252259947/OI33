# 实名账号、班型与作业：实现与启用指南

本次改动仍是 OI33 插件扩展，没有修改 Hydro 核心或评测引擎。本文件描述本地实现，不代表已推送 GitHub、部署腾讯云或完成生产数据迁移。

## 1. 确定的使用方式

保留注册入口，日常用户采用「注册 → 提交真实姓名等资料 → 管理员审核 → 正常使用」。同时保留管理员按已核验名单批量创建正式账号、临时比赛账号的入口。

- 未审核日常账号可以登录、浏览原本公开的内容、维护申请与账号安全；不能提交代码、领取作业、参赛或发文章等业务写操作。原有 Hydro 权限仍然生效，不会因为实名审核而自动获得额外权限。
- 实名是人工核验档案，不是公安/运营商接口认证；管理员必须线下核对名单。姓名、学号、学校及申请班型不是公开个人资料。
- 「身份是否通过审核」「正式/临时用途」「启用状态与有效期」「域角色」分别存储和判断。学生申请的班型文字不会自动变成分组，更不会授予教练或管理员权限。
- 临时账号只能访问指定比赛、比赛内题目及本人的相关记录；不能浏览 unrestricted 题库、作业、文章或跨比赛记录。范围限制不替代比赛原有报名、题目及分组权限。
- 到期和停用是权限限制，不删除账号、UID、成绩或提交记录。管理员可以恢复、延期，或把已核验临时账号转成正式账号；主动停用的账号转换用途后仍须单独恢复。

## 2. 角色与边界

| 身份 | 可以做什么 |
| --- | --- |
| 学生 | 查看有权访问的作业、领取和提交、查看自己的待完成任务 |
| 教练（域角色 `coach`） | 管理当前域班型、创建作业、管理自己创建或参与协作的作业及全员完成情况 |
| 管理员 | 审核实名、管理账号状态、批量建号、显式设置教练角色；同时拥有教学管理入口 |

兼容 Hydro 超级管理员、当前域 `root` 和原 OI33 管理员标记。新的教练角色不会由实名审核、班型标签或用户自填内容产生。现有自定义角色不会被一键设置覆盖；原生 Hydro 权限不足时，管理入口也不能绕过它。

班型是对 Hydro 域分组的教学化使用，一个学生可以加入多个班型，作业向所选班型的**并集**开放。加入两个选中班型的学生只统计一次。

教学成员必须确实加入当前域（`domain.user.join=true`），或拥有当前域的实名申请档案。不能利用 Hydro 对外域 UID 返回的默认 guest 对象探测外域实名。临时比赛账号不能加入教学班型或应交名单；旧分组包含这类用户时，发布/预览会提示清理，不会悄悄纳入缺交统计。

教练目前可维护本域所有教学班型；没有引入「每个班型只有特定教练可以管理」的二级权限体系。

## 3. 作业与训练的分工

- **训练**保留原来按章节组织、长期自主练习的功能，不改变它的规则。
- **作业**复用 Hydro 原作业题目、提交、截止时间及计分，同时补上固定应交名单与教师全员统计，只有教练/管理员能创建。
- 顶部导航按：首页、题库、作业、训练、比赛、讨论、测评记录、排名。取消桌面「更多」折叠菜单，窄屏使用原移动导航。
- 首页快捷入口中的「训练」改为「作业」；首页内容区在比赛与训练之间加入作业。欢迎卡片里的「继续训练」保留。

### 可访问范围与应交名单分开

| 数据 | 规则 |
| --- | --- |
| 当前访问权限 | 按现在的域分组与 Hydro 权限动态判断 |
| 应交学生 | 新作业发布时，把所选班型成员去重后固定下来 |
| 完成情况 | 对固定名单每个人计算本作业内逐题 AC，包括未领取和从未提交的人 |
| 转班 | 不自动删除原应交记录；移出开放班型后可能失去访问权，教练应按实际情况免除或补发 |
| 新同学 | 不偷偷加入历史应交名单；教练先预览，再确认同步或补发 |

完成情况提供应交、已完成、进行中、未开始、逾期未完成、已免除汇总，以及逐人逐题表格。练习区以前的通过记录不直接当成本作业已完成。逾期按 Hydro 作业的准时截止时间（`penaltySince`，缺失时用 `endAt`）判断。

应交名单管理支持初始化旧作业、同步新增成员、补发、填写原因后免除。预览绑定操作人、域、作业、名单版本，10 分钟过期；并发修改后必须重新预览。同步仅补充，不删除转班学生，不撤销已有免除。

固定的是成员名单；编辑作业题目或截止时间仍沿用 Hydro 行为，会影响完成度计算，不是题目/规则的历史版本快照。

## 4. 页面入口

下表是主域路径；其他域使用 Hydro 正常域前缀 `/d/<domainId>`，不能用 query/body 的 `domainId` 冒充目标域。

| 页面 | 路径 | 权限 |
| --- | --- | --- |
| 实名与账号 | `/oi33/enrollment` | 本人；头像下拉菜单有入口 |
| 实名审核与账号状态 | `/oi33/enrollment/review` | 管理员；支持状态、UID 筛选 |
| 批量建号 | `/oi33/accounts/batch` | 管理员 |
| 批次预览和确认 | `/oi33/accounts/batch/<id>` | 原批次创建管理员、原域 |
| 教学权限设置 | `/oi33/education/access` | 管理员；创建教练角色及指定教练 |
| 班型管理 | `/oi33/education/classes` | 教练/管理员 |
| 作业全员完成情况 | `/oi33/education/homework/<tid>` | 作业创建者/协作者中的教练，或有原生编辑权限的管理员 |
| 我的作业 | `/oi33/education/tasks` | 登录学生；包含有权访问但未领取的应交作业 |

## 5. 批量建号

输入支持从表格复制的 TSV 或 CSV，每批最多 200 人：

```text
用户名,姓名,学号,已有UID
student_001,示例学生甲,S001,
student_002,示例学生乙,S002,42
```

1. 先选择用途和班型。临时比赛批次不要选择教学班型，必须填写带时区的有效期及当前域比赛 ID，只能创建新专用账号，不得关联已有正式账号。
2. 点击预览。此时只保存待确认批次，不创建用户、不分班、不改变权限。预览 30 分钟过期。
3. 管理员核对真实身份并勾选确认后执行。新账号先以不可登录状态创建，身份与班型配置成功后才启用。
4. 初始密码随机且逐人不同，只在此次响应中显示，不保存在批次预览、审计日志或 URL。及时安全发放。新正式账号首次使用须修改初始密码；占位邮箱不能收信，丢失密码由管理员重置。
5. 已有 UID 必须与用户名、已核验姓名、当前域身份一致。只添加班型，不覆盖角色、权限位、密码或身份档案。
6. 部分失败后只重试未完成行；已创建 UID 不重建、密码不重置。中断超过处理锁有效期后，可从原批次页重试。若账号创建状态不确定，停止该行并人工核对，绝不按同名账号自动接管。

## 6. 数据与兼容

| 存储 | 用途 |
| --- | --- |
| Hydro `user` / `domain.user` | 原账号、密码哈希、UID、域成员关系与角色 |
| Hydro 原生用户分组 | 多班型成员及原生访问控制 |
| Hydro contest/homework 与提交状态 | 原作业、比赛及评测记录 |
| `oi33_enrollment` | 权威身份档案、状态、临时范围、版本与私有审核历史 |
| `oi33_enrollment_pretest` | 临时比赛账号的自测记录与指定比赛映射 |
| `oi33_account_batch` | 批量预览、逐行状态、处理锁和审计定位；无明文密码 |
| `oi33_education_roster` | 固定应交名单及免除状态 |
| `oi33_education_preview` | 短期名单变更预览 |
| `oi33_log` | 操作审计；实名与密码不写入普通活动日志 |

- 旧的 `realname_flag >= 1` 身份在没有新档案时继续兼容，不批量写库、不强制重审；原管理标记不会被实名同步降级。
- 新实名档案与旧 `realname_flag` 兼容同步只有普通 0/1，不把新姓名复制进公开 User 对象。旧实名修改/申请审批入口不能再覆盖新档案或申请管理身份。
- 旧用户不会自动出现在新身份档案审核列表。旧实名纠错和旧账号批量迁移尚未提供新专门界面，不能把“兼容”理解成“迁移完成”。
- 不会自动建立旧作业应交名单。进入完成情况页，预览当前班型后才可以确认初始化。
- 作业创建与名单写入不是跨集合事务。如原作业创建成功而快照失败，显示恢复页面，提示不要重发创建请求；使用已创建作业的完成情况页补建名单。
- 私有页面禁止浏览器/代理缓存。新门禁检查当前数据库状态，同时限制旧登录会话、提交接口与长连接。保留经过原生验证的内部 WebSocket 网关，不将浏览器自报的身份当成可信内部身份。
- 仅无学生身份档案且持有原生评测服务权限的评测机专用接口继续按 Hydro 服务身份鉴权，不要求评测机登记学生姓名。

## 7. 上线顺序与回滚注意事项

本次代码没有自动部署。上线应在确认备份和测试结果之后独立执行：

1. 备份现有插件、数据库和运行配置；核对当前管理员及评测服务身份、学生账号旧实名状态。不要在生产批量改 UID、权限位或旧名单。
2. 在测试实例加载完整插件组合，检查导航、登录、在线编程、自测/提交、原作业与新增教学页面。新增模块的隔离测试不能替代全部旧功能回归。
3. 管理员明确确认上线窗口后更新插件并重启；新门禁随插件生效，没有默认关闭的灰度开关。此前未实名但能提交的普通旧账号将需要走审核，需提前通知。
4. 打开「教学权限设置」，显式创建 `coach` 角色并指定教练。不覆盖已有同名角色；若已存在则先核对其实际权限。
5. 建立班型、审核首批学生，用一份真实教学作业验证。旧作业根据需要逐个初始化应交名单，不做全库自动迁移。
6. 临时比赛先用专用测试批次验证范围、报名、有效期及程序评测，再发正式名单。测试消息/提交应取得站点管理者批准。

回滚插件代码不会删除新增集合，但也会撤掉新门禁，临时账号的范围/到期限制将不再由本模块执行。回滚前必须先按管理员确认的名单在 Hydro 层停用临时账号或限制登录，不能只替换旧版本就认为账号仍被安全限制。不要删除身份或历史提交集合来回滚界面。

## 8. 验证方式与未包含内容

```sh
npm test
```

默认自动化覆盖解析、身份状态、并发审核、批次幂等、权限、名单规则、模板和导航。浏览器尺寸回归与真实 Hydro/MongoDB 隔离验证另见 `tests/homepage-navigation.test.cjs`、`tests/live/README.md`。

隔离集成验证使用独立端口、独立数据库及合成身份，不修改正在运行的实例。它不启动评测机，不证明真实程序评测可用，也不是生产部署验收。

本轮没有新增身份证/人脸认证服务、短信认证、邀请注册码、审批通知、Excel 文件上传、自动发密码、已批准姓名纠错专门表单、班型负责人二级授权或生产数据迁移脚本。注册入口本身、原训练/作业和评测功能继续复用 Hydro。
